## 🎯 Цель работы
Разработать и отладить программный прототип системы на языке **C++**, используя командную модель разработки **Git-Flow**, с соблюдением единого Code Style, изоляцией функционала по веткам и слиянием через Pull Requests.

---

## 👥 Состав команды и распределение ролей

Разработка велась строго в персональных функциональных ветках с последующим слиянием в `main` через процедуру Pull Request (PR):

| Участник | Роль в проекте | Ветка разработки | Реализованные модули |
| :--- | :--- | :--- | :--- |
| **Участник 1** | Frontend / Клиентская часть | `feature/customer-cart` | `Customer.h` (профиль покупателя), `Cart.h` (корзина) |
| **Участник 2** | Backend / База данных | `feature/database-product` | `Product.h` (каталог), `ShopDatabase.h` (паттерн Singleton) |
| **Участник 3** | Fullstack / Менеджер / QA | `feature/order-manager` | `Order.h` (заказы), `Manager.h` (панель сотрудника), `main.cpp` |

---

## 📐 Архитектура и реализованные паттерны

Система построена в строгом соответствии с UML-моделью (Лабораторная работа №2):
* **Паттерн Singleton (Одиночка):** Реализован в классе `ShopDatabase` для обеспечения глобальной единой точки доступа к каталогу товаров и заказам.
* **Наследование и инкапсуляция:** Разделение прав доступа акторов системы (`Customer` и `Manager`).
* **Моделирование бизнес-процессов:** Проверка складских остатков перед добавлением в корзину и смена статусов заказа при подтверждении менеджером.

---

## 📝 Единый Code Style проекта

Между всеми участниками команды соблюдены следующие правила оформления кода:
1. **Именование классов:** `PascalCase` (например, `ShopDatabase`, `Customer`).
2. **Именование методов и полей:** `camelCase` (например, `addProduct()`, `totalPrice`).
3. **Защита от повторного включения:** Директива `#pragma once` во всех заголовочных файлах.
4. **Отступы:** 4 пробела (без использования табуляции).
5. **Кодировка файлов:** `UTF-8` (с явным включением `CP_UTF8` для консоли Windows).
